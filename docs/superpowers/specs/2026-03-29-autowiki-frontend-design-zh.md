# AutoWiki 前端设计规范

> **[已完成]** 已实现并合并（PR #4 + frontend-redesign 分支）。当前技术栈：Next.js 16.2.1、React 19、Tailwind v4（仅 CSS，无 `tailwind.config.ts`）、`@base-ui/react`（取代了 `@radix-ui/react`）。此处描述的配色方案和布局与已发布的 UI 一致。

## 概述
本文档概述了 AutoWiki 前端的设计视觉和布局结构，其灵感主要来自 `deepwiki.com` 和 `zread.ai` 等平台简洁、现代的美学。目标是为浏览 AI 生成的仓库文档提供一个高度可读、直观的界面。

## 全局样式（首选浅色模式）
*   **主题：** 以浅色模式为主。将支持深色模式，但浅色模式是默认且经过优化的目标。
*   **配色方案：**
    *   背景：纯净白（`bg-white` 或 `bg-slate-50`）。
    *   文本：高对比度以增强可读性（主要文本使用 `text-slate-900`，次要文本使用 `text-slate-500`）。
    *   边框：细微且不突兀（`border-slate-200`）。
    *   强调色：主色调（例如淡蓝色或靛蓝色），用于激活状态和主要按钮。
*   **字体：** 无衬线字体，利用系统字体或 Inter/Geist。侧重于层级结构，标题（粗体、较大）与正文（常规、高度易读的行高）之间有明确区分。
*   **间距：** 宽裕的内边距和外边距（`p-4`、`p-6`、`gap-4`），以营造呼吸感强、整洁的界面。

## 1. 首页布局

首页作为入口点，侧重于搜索和发现。

### 结构
1.  **英雄区 (Hero Section)：**
    *   居中对齐。
    *   清晰、简洁的标题（例如，“探索开源知识”）。
    *   **搜索栏：** 醒目且宽大。支持对已索引仓库的模糊搜索，并接受直接输入的 GitHub URL 以进行即时索引/导航。
2.  **最近/精选仓库（网格视图）：**
    *   显示最近索引的 20 个项目。
    *   布局：响应式网格（例如，中屏 2 列，大屏 3-4 列）。
    *   **仓库卡片：**
        *   简洁的卡片设计，带有细微边框和悬停效果（例如，轻微提升或边框颜色变化）。
        *   **内容：**
            *   仓库名称（Owner/Repo 格式）。
            *   简短描述（截断为 2 行）。
            *   **元数据页脚：** 语言图标/颜色、Star 数量（例如，⭐ 12.5k）以及最后更新时间（例如，“2 小时前索引”）。

## 2. Wiki 页面布局（三栏式）

Wiki 页面优先考虑深度阅读和结构化导航。

### 结构
布局分为三个不同的列：

1.  **左侧列：全局侧边栏（导航）**
    *   固定位置或粘性定位。
    *   包含分层的“Wiki 计划”（文档的目录/页面结构）。
    *   当前活动页面的视觉指示。
    *   可折叠的深层嵌套内容。
    *   宽度：约 250px - 300px。

2.  **中间列：主内容区**
    *   可滚动。
    *   限制最大宽度以获得最佳阅读体验（例如，`max-w-3xl` 或 `max-w-4xl`）。
    *   丰富的 Markdown 渲染（标题、带有语法高亮的代码块、表格、列表）。
    *   宽裕的行高和段落间距。

3.  **右侧列：“本页内容”（目录）**
    *   粘性定位。
    *   根据当前页面的 Markdown 标题（`<h2>`、`<h3>`）动态生成。
    *   随着用户滚动主内容而突出显示活动章节。
    *   提供快速的页内导航。
    *   宽度：约 200px - 250px。在较小屏幕上隐藏。

## 3. 交互功能 UI

为了将交互功能（聊天、图表、刷新）无缝集成到新的美学中，这些组件将被视为阅读体验的核心部分，而不是孤立的页面。

### 聊天面板 (ChatPanel) UI
*   **位置：** 聊天功能不使用单独的全页面路由，而是通过右下角的悬浮操作按钮 (FAB) 全局可用，或者作为一个可折叠/可调节大小的右侧抽屉，暂时替代“本页内容”目录。这符合在 `zread.ai` 和 `deepwiki.com` 上看到的“边读边问”的连续工作流。
*   **视觉风格：**
    *   **助手消息：** 浅灰色/蓝色背景（`bg-slate-50`），占满聊天容器宽度，具有清晰的 Markdown 渲染和代码块语法高亮。
    *   **用户消息：** 鲜明的品牌色（`bg-indigo-600`，`text-white`），向右对齐。
    *   **引用：** RAG 模型引用的源文件应作为消息下方的可点击药丸状标签。
*   **输入区域：** 固定在聊天面板底部，具有自动扩展的文本区域和细微的“发送”图标。流式传输期间的禁用状态必须在视觉上清晰可见（例如，脉动打字指示器）。

### 依赖图 (DependencyGraph) UI
*   **位置：** 通过顶部导航的切换开关或左侧侧边栏中专门的“架构”标签页访问。
*   **视觉风格：**
    *   **画布：** 使用 `reactflow`，带有干净的 `bg-slate-50` 点状或网格背景。
    *   **节点：** 现代圆角矩形（`rounded-xl`），具有纯白背景、细微边框（`border-slate-200`）和清晰的无衬线字体显示模块名称。徽章或辅助文本指示文件数量。
    *   **连线：** 中性灰色的平滑、抗锯齿贝塞尔曲线。
    *   **控件：** 左下角悬浮的极简缩放/平移控件。

### 刷新索引 (RefreshIndex) UI
*   **位置：** 集成在页眉或左侧侧边栏顶部，紧邻仓库名称。
*   **视觉风格：** 细微的图标按钮（例如，同步/刷新箭头）。
*   **交互：**
    *   **空闲：** 标准灰色图标。
    *   **激活/索引中：** 图标旋转（`animate-spin`），并有极简进度条或工具提示指示任务状态。
    *   **成功：** 在返回空闲状态前，短暂闪烁绿色并显示复选框。
    *   **动作：** 触发 `POST /api/repos/{repo_id}/refresh` 接口，而无需强制刷新页面，仅在完成后获取新树。

## 交互元素
*   **搜索：** 随时随地可访问的快速导航模态框 (Cmd+K/Ctrl+K)，与首页搜索功能保持一致。
*   **过渡：** 快速、近乎即时的页面加载（利用 Next.js 路由），交互元素具有细微的状态变化。

## 实现注意事项 (Tailwind CSS)
设计将严格使用 Tailwind CSS 工具类实现，遵循项目现有的 v4 配置（仅 CSS 方案）。
